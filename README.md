# CS-360
The app I developed, Healthy Way, was created to meet the user need of tracking weight and staying motivated toward health goals. The main requirements included a login screen where users could create or access an account, a weight input and display screen where entries could be added and viewed, and an SMS permissions screen that allowed users to opt into receiving notifications when they reached milestones. The overall goal was to provide a simple, user-friendly way for users to monitor their progress without unnecessary complexity.
Several screens were necessary to support these needs. The login screen ensured that users could create a secure account and return to their saved data. The weight screen combined input fields for date and weight with a grid display that showed all entries clearly. Finally, the SMS permissions screen was included so users could decide whether to allow the app to send text message notifications. When designing these screens, I focused on usability by keeping layouts clean, using logical visual flow, and making sure that elements did not overlap or confuse the user. For example, I positioned the SMS notification button at the top of the weight screen so it was easy to find but not disruptive to the main purpose of entering data. These design choices were successful because they kept the user’s tasks straightforward and intuitive.
My approach to coding the app was to build it step by step and test each part as I went. I started with the basic layouts in the Android Studio Layout Editor, then connected activities like the login and weight input screens. I also added runtime permission checks for SMS so that the app could handle both approval and denial. Throughout the process I relied on strategies such as commenting my code, testing frequently in the Android Emulator, and solving one problem at a time instead of trying to finish everything at once. These techniques helped me stay organized and could be applied to future projects by ensuring that I build in manageable pieces rather than overwhelming myself with the full project at once.
Testing in the emulator was especially important. I tested the app by entering different weight values, navigating between screens, and responding both ways to the SMS permission prompt. This process showed me where layout issues existed, such as when elements overlapped, and it also revealed logic errors like when the app didn’t properly update the permission status. Testing allowed me to make corrections before finalizing the project, which is a critical part of development.
One area where I had to innovate was solving layout challenges. At first, the SMS button conflicted with the input fields on the weight screen. To fix this, I restructured the layout constraints to give each element proper spacing. It took some trial and error, but finding the right design solution improved the overall usability of the app.
The component I was most successful in was implementing SMS permission handling. I was able to show that I understood how to request permissions at runtime, update the UI based on the user’s choice, and ensure that the rest of the app continued to function even if permissions were denied. This feature demonstrated both technical skill and attention to the user experience, which I consider one of the strongest parts of my project.
