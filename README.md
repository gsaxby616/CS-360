# CS-360
The app I developed, Healthy Way, was designed to meet a common user need: tracking weight and receiving encouragement to meet health goals. The main requirements included the ability for users to log in, securely create an account, add and update weight entries, and view their progress in a simple grid format. Another important requirement was the ability to request permission for SMS messaging, so users could receive optional notifications when milestones were achieved. The overall goal was to provide an app that simplified daily health tracking while respecting user privacy and focusing on usability.
To meet these needs, several screens were necessary: a login screen, a weight entry and display screen, and an SMS permission screen. The login screen ensured secure access while providing an option for new users to create accounts. The weight tracking screen combined input fields with a grid display, making it easy to enter, view, and manage data. The SMS screen allowed users to control permissions and choose whether or not to enable alerts. I designed the UI with users in mind by focusing on clarity, logical flow, and avoiding clutter. For example, I positioned the SMS notification button at the top so it was accessible but not disruptive to the main task of weight logging. These designs were successful because they guided users naturally through the app’s functions without unnecessary complexity.
My approach to coding the app involved breaking the project down into smaller pieces, such as first building the database shell, then creating the CRUD operations, and finally integrating them into the UI. I relied on iterative testing in the Android Emulator to confirm that each step worked before moving on to the next. Using strategies such as commenting code for clarity, reusing modular functions, and testing frequently helped keep the development process organized and manageable. These techniques can be applied to future projects by ensuring that large development tasks are divided into achievable steps that can be validated incrementally.
Testing was a key part of the process. I tested by entering different types of data into the fields, checking how the app behaved when permissions were denied, and running the app in the emulator to confirm that CRUD operations worked as expected. This process was important because it revealed issues like overlapping UI elements, incorrect constraints, and permission errors early on, allowing me to fix them before finalizing the app.
Throughout the project, I had to innovate in order to solve layout challenges. For example, the SMS notification button originally interfered with the weight input fields, and I had to rework the constraints to improve usability. This required thinking creatively about how to structure the layout while still meeting the design requirements.
The component where I was particularly successful was in integrating the database with the UI. I was able to demonstrate my understanding of Room database operations and how to connect them with RecyclerView to display user-entered data. This part of the project showed not only my technical coding skills but also my ability to connect backend functionality with a user-centered interface, which is essential in mobile app development.
